# AgentLens — Code Walkthrough

Read this top to bottom once, then use it as a map. Every claim below is about code that exists in this repo;
where something is *not* built or *not* verified, it says so.

## 0. The one-paragraph version

A user asks a question about SEC filings. An **agent** (an LLM in a loop) calls **tools** (EDGAR lookups, a calculator),
and finally calls `submit_answer`. Every LLM call and tool call is recorded as a **span** in a **trace**. An **eval harness**
runs the agent over a **golden dataset** many times, scores each run deterministically, classifies every failure into one of
15 categories, and produces a report with confidence intervals and paired significance tests. A **dashboard** visualises
traces and eval results. A **gateway** (Python/FastAPI) is the control plane that sits between dashboard and agent, stores traces
in Postgres, and enforces auth/rate/cost limits.

```
Dashboard (Angular) ──REST/SSE──▶ Gateway (FastAPI) ──NDJSON stream──▶ Agent service (FastAPI)
                                       │                                        │ MCP
                                    Postgres                          edgar-mcp · calc-mcp (tools/)
Eval CLI (evals/) ── direct mode: runs the Agent in-process, writes JSONL, no gateway/DB needed
```

## 1. The event protocol — `agent/src/agentlens_agent/events.py`

The agent service talks to everything else in **NDJSON** (one JSON object per line), each with a `kind`:

- `run.started` → `span.finished` (many) → `run.finished`. (`span.started` is defined for live in-flight display but not emitted.)
- A **span** = one unit of work: `llm_call`, `tool_call`, or the root `agent` span. Fields: `span_id`, `parent_span_id`, `seq`,
  start/end time, `input`, `output`, `usage` (tokens), `cost_usd`, `status`, `attributes`.
- **Span IDs are generated by the agent (UUIDs)**, so the gateway can upsert them: replaying a stream is harmless (idempotency).
- **The root span is emitted last** and gets the final `seq`, because it ends last and carries the run totals. That's why the DB
  has *no foreign key* on `spans.parent_span_id` (children are stored before their parent). Early drafts of the spec said
  otherwise; the code and DB follow this.
- `to_wire` / `from_wire` serialise/parse; `scripts/export_schemas.py` exports the JSON Schema to `contracts/`, and
  `validate_contracts.py` fails CI on drift.

## 2. The agent — `agent/src/agentlens_agent/`

### `answer.py` — the terminal tool
Instead of parsing free text, the model finishes by calling a tool `submit_answer` whose schema is the pydantic `Answer`:
`abstained`, `value`, `unit` (USD, USD_millions, percent…), `period`, `text`, `citations[]`. This gives provider-neutral
structured output and an unambiguous "done" signal. `abstained=true` is first-class because *refusing to answer unanswerable
questions* is something we measure.

### `config.py`, `cost.py`
- `AgentConfig`: everything that defines an agent variant (model, prompt id, temperature, max_steps, budget, tool allow-list).
  The gateway snapshots it immutably and hashes it.
- `load_system_prompt` returns text **and SHA-256**, so prompt drift is visible in results.
- `PricingTable`: prices come from `config/pricing.yaml` (you fill it from the provider's page; **never hardcoded** — they change).
  `MissingPriceError` if a model has no price. Cache-read tokens are priced separately.

### `llm/base.py` — the only thing the loop knows about LLMs
Neutral dataclasses (`Message`, `ToolCall`, `ToolResult`, `ToolSpec`, `LLMResponse`) and a `LLMClient` Protocol with one method
`complete(...)`. `LLMError(retryable=...)` is how adapters tell the loop whether a retry makes sense.
- `llm/anthropic_client.py` translates neutral ↔ Anthropic Messages API (`to_anthropic_messages`, `parse_anthropic_response`).
  Tested with canned payloads; **never run against the live API**.
- `llm/fake.py` — `ScriptedLLM` replays pre-written responses; this is how the whole loop is tested with no network.

### `registry.py`, `mcp_registry.py` — tools
`ToolRegistry` is a Protocol: `specs(allowlist)` and `call(name, args) -> ToolOutput(content, is_error)`. Contract: **tool
failures are returned, not raised** — the model should see the error and adapt.
`StaticToolRegistry` is the in-memory test double. `McpToolRegistry` is the real one:
- Servers are configured as `name -> target`, where target is `http(s)://…` (streamable HTTP, used in compose) or
  `stdio:<cmd args>` (spawn locally, used in tests/dev).
- `connect()` opens a session per server, lists tools, builds name→server (duplicate names = config bug, raises).
- `call()` wraps every failure mode (unknown tool, MCP `is_error`, timeout, transport death) into `ToolOutput(is_error=True)`.
  If the transport itself died it **reconnects that server once and retries once** (safe because all tools are read-only).
- Uses MCP Python SDK **v2** (`mcp.Client`) — v1 snippets online don't apply.

### `loop.py` — the heart (read this file in full)
`AgentRunner.run(question)` is an **async generator**: it `yield`s events as they happen, so the caller streams them.
Flow per step (a step = one *successful* LLM response, max `max_steps`):

1. **Call the LLM** with up to 3 attempts. Retryable errors (429/5xx/timeout) back off exponentially with jitter
   (`0.5s · 2^(n-1) · (0.5…1.5)`). *Each attempt is its own span*, failed ones marked `status=error`, so you can see retries in the trace.
2. **Price the call** and add to the running cost; if over `max_cost_usd` → stop with `budget_exceeded`.
3. **`submit_answer` called?** Validate against `Answer`. Invalid → feed the validation error back, allow **one repair**; still
   invalid → accept raw text and flag the root span `invalid_answer=True` (scored as `format_error`).
4. **Plain text, no tool call?** Nudge once ("call submit_answer"); still nothing → accept as answer with `no_submit=True`.
5. **Otherwise run the tool calls concurrently** (`asyncio.gather`), enforce the allow-list *in the loop* (not trusting the
   model), truncate outputs over 12,000 chars with a visible marker (+ `truncated`, `original_size` attributes), emit a
   `tool_call` span for each, append results, loop.
6. If the `for` loop runs out of steps (the `for…else`) → `step_limit`.
7. Finally emit the **root span** (totals, `steps`, `retries`, `truncations`, flags) and `run.finished`.

Design choices worth being able to defend in an interview:
- **No LangChain/LangGraph**: ~390 lines you fully understand beat a framework you can't debug; and evaluation needs exact control of spans.
- **Failures never raise out of the generator** — they become spans + a `termination_reason`. The one deliberate exception is a
  missing price, which raises in `__init__` *before any money is spent*.
- **Cancellation is not caught** (`CancelledError`) so a client disconnect stops spending immediately.
- Time and randomness (`sleep`, `rng`) are injected → retry tests run instantly and deterministically.
- LLM-span inputs store only *new* messages (deltas), not the whole conversation each time — keeps traces small.
- `tool_failure` termination is reserved/unused: tool errors are recoverable by design.

### `wiring.py`, `main.py` — the HTTP service
`build_runner` assembles LLM + registry + pricing. `main.py` is FastAPI: lifespan **connects to MCP servers at startup and
fails fast** (an agent without tools is broken); `POST /v1/agent/run` returns a `StreamingResponse` of NDJSON; a missing price → HTTP 422.

### Tests (`agent/tests`, 37 pass)
`test_loop.py` (19) is the executable spec: invariants (one `run.finished`, strictly increasing `seq`, unique ids), retries,
budget, step limit, repair/nudge paths, concurrency (sleeping fake tools), allow-list, truncation. `test_mcp_registry.py` (7)
spawns a real calc-mcp over stdio and checks that `SEC_USER_AGENT` is forwarded to stdio tool servers (the MCP SDK does *not*
inherit your environment — a bug found while preparing the run docs). `test_main.py` (5) drives the real FastAPI route with a scripted LLM.

## 3. Tools — `tools/src/agentlens_tools/`

- `calc.py` — **safe calculator**. Parses with `ast` and whitelists node types (never `eval`). Rejects huge exponents and
  division by zero; accepts thousands separators; adds `pct_change` and `cagr`. Why a tool at all? LLMs are bad at arithmetic,
  and the eval classifies `calc_error` separately from retrieval errors.
- `edgar_client.py` — `SecClient`: required declared User-Agent (SEC policy), throttled to ~8 req/s, disk cache, retries.
- `edgar_parse.py` — **pure** (no network) parsing: normalise CIK, match company, list filings, search XBRL concepts,
  select facts, HTML→text, extract a 10-K item. Encodes real gotchas: XBRL `fy`/`fp` describe the *filing*, not the fact's period
  (so select by `start`/`end` dates); the same period appears in many filings (de-dup, keep latest); 10-K tables of contents
  repeat "Item 1A" (take the longest span).
- `edgar_server.py` — MCP server exposing 5 read-only tools: `resolve_company`, `list_filings`, `search_xbrl_concepts`,
  `get_financial_facts`, `get_filing_section`. Filing text is returned under the key `untrusted_text` (prompt-injection
  hygiene; the system prompt tells the model to treat it as data).
- **Not verified:** nothing here has hit the real SEC API (TL-04 is yours to do).

## 4. Evaluation — `evals/src/agentlens_evals/`

This is the part that makes the project more than a demo.

- `case.py` — `EvalCase` (pydantic): question, `category` (lookup/calc/text_extract/multi_hop/unanswerable), `difficulty`,
  `expected` (numeric w/ unit, period, relative tolerance; or text must-contain; or abstain), `required_tools`, `provenance`
  (where the gold came from + who verified), `status` draft/verified, `split` dev/test (held-out).
- `scorers/` — `numeric.py` (convert to a base unit then compare within tolerance; units and period must match), `grounding.py`
  (is the answer's number actually present in tool outputs? are cited accession numbers real?), `tooluse.py` (required-tool
  recall, redundant and erroring call rates).
- `trace.py` — derives `TraceFacts` from the event stream: what tools were called, what numbers/accessions appeared in outputs,
  whether the last call errored. **Facts come from the trace, never from the model's claims.**
- `score.py` — `score_run`: a run *passes* only if it terminated `answered`, the answer was well-formed, and the answer is
  correct. Everything else (grounding, citations, tool recall) is **diagnostic, not part of pass/fail**.
- `classify.py` — every failure gets exactly one of **15 categories** via ordered rules (first match wins):
  1 provider_error · 2 step_limit · 3 budget_exceeded · 4 format_error · 5 missed_abstain · 6 false_abstain ·
  7 tool_error_unrecovered · 8 unit_error · 9 wrong_period · 10 calc_error · 11 hallucinated_number · 12 wrong_tool ·
  13 bad_args · 14 retrieval_miss · 15 other. Rules 1–6 are facts; 7–14 are heuristics — **validate against hand-labelled
  failures before quoting agreement numbers**. A test asserts this list equals the DB `CHECK` constraint.
- `stats.py` — Wilson 95% interval and exact two-sided McNemar test (dependency-free).
  With ~80 cases, differences under ~10 points are mostly noise, so every number ships with an interval.
- `compare.py` — paired comparison on shared cases (regressed/improved lists, McNemar p) and the **regression gate**
  (absolute floors + significant regression vs baseline → non-zero exit for CI).
- `runner.py` — `run_eval`: dataset × repeats with bounded concurrency; **resumable** (skips finished pairs in
  `results.jsonl`); **hard budget** (stops *starting* runs when spend + in-flight reservations would exceed `--budget-usd`,
  using an `asyncio.Condition` so valid runs wait rather than get skipped); a crash in one run is recorded, not fatal.
- `report.py` — markdown report: pass rate ± CI (case-level), cost per success, latency p50/p95, per-category pass rates,
  failure-category breakdown, groundedness diagnostics.
- **Case-level pass = strict majority of repeats; a tie fails.** (Why: one lucky sample shouldn't count.)
- `cli.py` — `agentlens-eval validate-dataset | run | report | compare`. `run` flags include `--budget-usd`, `--repeats`,
  `--split`, `--limit`, `--verified-only`, `--gate --baseline`. Exit code 3 = budget stopped the run.
- **Not done:** the golden set (`golden_v0.jsonl`) is a stub — EV-02, authoring ≥60 hand-verified cases, is *your* job and the
  single most important quality lever. No real eval run has happened, so there are no real results.

## 5. Database — `gateway/migrations/`

- `V1__init.sql`: `api_keys` (hash only), `agent_configs` (immutable, unique `config_hash`), `datasets`/`eval_cases`,
  `eval_runs` (partial unique index = at most one baseline per dataset), `runs`, `spans` (generated `latency_ms` column,
  `UNIQUE(run_id, seq)`), `eval_results` (`CHECK passed = (failure_category IS NULL)` — failures *must* be categorised), views.
- `V2__case_level_metrics.sql`: V1 computed pass rate per attempt while the docs/CI used per case. V2 adds
  `eval_case_outcomes` and recreates `eval_run_metrics` with case-level `pass_rate`, `n_cases`, `n_cases_passed`, plus
  `run_pass_rate`. (A real spec/implementation mismatch I found and fixed.)
- `scripts/smoke_schema.py` applies both migrations to a throwaway Postgres and asserts the constraints and views.

## 6. Dashboard — `dashboard/src/app/` (Angular 21)

Standalone components + **signals**, strict TypeScript, new control flow (`@if/@for`), Chart.js, typed API client generated

- `core/` — `api.service.ts` (typed HTTP), `auth.service.ts` + `auth.interceptor.ts` (API key in **sessionStorage only**,
  `X-API-Key` header, a 401 logs out), `runtime-config.ts` (`/config.json` → `{apiBaseUrl, demo}`; the same build serves
  demo and real mode), `sse.ts` + `run-stream.service.ts` (live run updates; implemented with `fetch` and a hand-written SSE
  parser because `EventSource` cannot send headers), `waterfall.ts` (pure layout math for the trace waterfall — unit tested),
  `pretty.ts` (unwraps JSON-in-JSON tool output), `format.ts`, `loadable.ts`, `problem.ts` (RFC 9457 errors).
- `shared/` — `trace-waterfall` (the signature visual: spans as time bars), `chart`, `json-view`, `state-view`
  (loading/error/empty), `status-chip`.
- `features/` — `login`, `overview` (spend vs cap), `runs` (filters + paging), `run-detail` (waterfall + span inspector),
  `playground` (ask a question), `evals` + `eval-detail` (failure-category chart), `compare` (paired comparison),
  `configs`. Routes: literal `evals/compare` is declared before `evals/:id`.
- **Demo mode**: `public/demo/**` is *synthetic* data generated by `scripts/gen_demo_data.py` (fictional companies, fake model
  names, scripted outcomes). The *code paths* are real (the real AgentRunner produced the traces; the real scorer, classifier
  and stats produced the verdicts) but **nothing in it is a benchmark result** and must never be presented as one.
- Verified: production build, 22 vitest tests, `scripts/ui_smoke.py` (Playwright: all routes, fails on console errors).
  **Never run against a live gateway.**

## 7. Gateway — `gateway/src/agentlens_gateway/` (Python, FastAPI + psycopg 3)

The control plane: it owns identity, spend limits, state and the public API. It never calls an LLM; it asks the agent service to.
One request, end to end: `POST /api/v1/runs` → **auth** → **rate limit** → **cost cap** → insert `queued` run → `RunExecutor` starts an
asyncio task → task calls the agent over HTTP and reads NDJSON → each `span.finished` is **upserted** in Postgres and **published** on the
`RunBus` → SSE subscribers get it live → `run.finished` closes the run and the stream.

| File | What it is / the idea worth understanding |
|---|---|
| `settings.py` | Frozen config from env vars; `validate()` refuses to boot with a weak admin key or `*` CORS. |
| `app.py` | `create_app()` factory + lifespan: validate → open pool → migrate → seed admin key → **recover stranded runs** → wire executor/bus/limiter. Shutdown ends in-flight runs as `failed/gateway_restart`. |
| `db.py` | Pool + a ~60-line migration runner: advisory lock (two replicas can't race), `schema_migrations` table, one transaction per file, **checksums** (editing an applied migration raises). |
| `store.py` | Every SQL statement lives here (raw SQL, no ORM). Routers stay thin; this is the file to read to learn the data model in action. Note `fail_run` rebuilds totals from `llm_call` spans only, because the root span repeats the totals (an early double-counting bug the tests caught). |
| `security.py` | `X-API-Key` → SHA-256 → lookup. Only hashes are stored. 401 carries `WWW-Authenticate`. |
| `ratelimit.py`, `costcap.py` | Pure functions with injectable clocks: token bucket per key; daily cap = spend today **+ reserved `max_cost_usd` of in-flight runs** (so ten concurrent runs can't jointly overshoot), with `Retry-After` until UTC midnight. |
| `executor.py` | `RunExecutor`: semaphore for max concurrency, `asyncio.timeout` per run, cancellation (user cancel vs timeout vs shutdown are distinguished), consumption loop `_consume`. |
| `bus.py` | In-process pub/sub: bounded queue per subscriber; a slow client is dropped (`LAGGED`) instead of blocking everyone. |
| `routes/runs.py` | Runs API + SSE. The SSE trick: **subscribe first, then read what's already in the DB, dedupe by span id** — no gap, no duplicate. 15 s keepalive comments; `X-Accel-Buffering: no` for proxies. |
| `routes/configs.py`, `datasets.py`, `evals.py` | Idempotent creates (same content → 200 and same id), eval runs, batch results, `compare` (reuses `agentlens_evals.compare`: one implementation of McNemar/Wilson for CLI and API), `/stats/overview`. |
| `problems.py` | RFC 9457 `application/problem+json` everywhere; unhandled exceptions return 500 without leaking internals. |
| `hashing.py`, `cursor.py` | `config_hash` (canonical JSON; temperature rounded; allowlist order ignored; `name` excluded) and keyset pagination tokens. |

Tests (`gateway/tests`, 84): real PostgreSQL 16 (embedded via `pgserver`; each test gets its own database cloned from a migrated template),
a scriptable `FakeAgent` (ok / block / unreachable / error midway / ...), SSE tests over a real uvicorn socket (ASGI test transports buffer
responses, which would hide streaming bugs), and `test_contract.py`, which fails if a route is missing from `contracts/openapi.yaml`, if the
spec documents a route that does not exist, or if a response does not match its schema. `scripts/stack_smoke.py` (`make stack-smoke`)
goes one level up: gateway + agent + the real calculator MCP subprocess + Postgres, only the LLM scripted.
